# ADR-0027 · Native platform constraints are handled by config plugins, never by editing ios/

## Context

The handoff asks for Expo development builds, EAS configuration, and a toolchain verified against the selected Expo release (handoff prompt:44). Two native problems appeared on the build machine. iOS 27 (Xcode 27 SDK) traps at launch unless the app adopts the UIScene life cycle, and the SDK 57 prebuild template still generates the old window setup. The repo lives under a path with spaces, which breaks the Expo Constants build phase and the React Native bundle script. `ios/` and `android/` are generated by `expo prebuild` and git-ignored, so hand edits there are lost on the next prebuild.

## Decision

Never edit `apps/*/ios` or `apps/*/android` by hand. Express every native change as configuration in `app.config.ts` or as a config plugin in the root `plugins/` folder, applied to both apps. Today: `plugins/with-scene-lifecycle.js` wires Expo's scene delegate into the AppDelegate and Info.plist; `plugins/with-ios-build-paths.js` quotes the Constants and bundle script paths through the Podfile and Xcode project.

## Consequences

- `expo prebuild --clean` can regenerate the native projects at any time without losing a fix; native fixes are reviewed like any code.
- Plugins patch generated code by string or regex replacement; an Expo SDK upgrade can change the generated text and break them. Only some failures are loud: `with-ios-build-paths` throws when the Podfile has no `post_install` hook, and `with-scene-lifecycle` throws on a non-Swift AppDelegate. The other replacements fail silently.
- The path plugin exists only because of the repo location; [ADR-0050](0050-repo-path-with-spaces.md) decides whether to keep it or move the repo.

## Alternatives considered

Committing `ios/` and editing it by hand: rejected by the ignore rule and the prebuild workflow (`README.md:100`, `:112`). Moving the repo to a path without spaces: open in [ADR-0050](0050-repo-path-with-spaces.md).

## Evidence

Line numbers at commit `c38429d`.

- Commits: `0fa0487` (2026-09-30) added `with-scene-lifecycle`; `c38429d` (2026-10-13) added `with-ios-build-paths` to both apps. Before `c38429d` the path fix existed only uncommitted, for the passenger app (backlog [QA-10](../status/backlog.md)).
- `plugins/with-scene-lifecycle.js:1-4` (reason), `:8-18` (AppDelegate), `:19-27` (Info.plist scene manifest).
- `plugins/with-ios-build-paths.js:1-2` (reason), `:28-36` (Podfile hook, throws without `post_install`), `:37-50` (Xcode bundle phase rewritten by regex).
- `apps/passenger/app.config.ts:31-34` and `apps/driver/app.config.ts:31-34` (both plugins listed).
- `.gitignore:5-6` (`ios/`, `android/` ignored).
- Enforced by: no automated test. A successful `expo prebuild` and Xcode build is the check (`README.md:97-114`).

## Revisit when

- Expo ships an SDK whose prebuild template adopts UIScene: delete `with-scene-lifecycle`, or
- [ADR-0050](0050-repo-path-with-spaces.md) moves the repo: delete `with-ios-build-paths`, or
- any Expo SDK upgrade: re-run prebuild and an Xcode build for both apps before anything else.
