(`SCENARIOS`, `DEMO_ACCOUNTS`, `buildSeed`). If this page and the seed disagree, the seed wins: fix this page.
Owner: build owner. Last verified: 2026-10-13 against `seed.ts` on branch `chore/docs-foundation-and-fixes`.

`services/demo-api/fixtures/`, generated by `services/demo-api/scripts/generate-fixtures.py`.

## Test cards (Salma)

Card payments are simulated. The outcome depends on the last four digits of the provider token (`rides.ts`):

| Card | Outcome |
|---|---|
| •••• 4242 | Confirmed by the simulated provider a few seconds after the ride |
| •••• 0002 | Declined (« Carte refusée par la banque émettrice. ») |
| •••• 3155 | Stays pending until someone resolves it (scenario launcher, or `POST /dev/providers/payment/<ref>/confirm` or `/fail`) |

Adding a card in the app (`card/new`) follows the same rule and shows the hint « 4242… acceptée · 0002 refusée · 3155 en attente ».

## Scenarios

| Scenario | Use it for |
|---|---|
| `default` | Full world: NY-001 (cash) and NY-002 (card) completed, Amina's wallet at 70 MAD, review queue, Leila in debt |
| `first-ride` | S03: no rides, Amina at 0 MAD; a cash ride NY-001 takes her to −15 MAD |
| `after-cash` | S04: NY-001 done in cash, Amina at −15 MAD; a card ride brings her to 70 MAD |
| `no-casablanca` | S15: Casablanca not configured yet; add it as a test city in the admin |
| `dynamic-pricing` | S06: dynamic pricing ×1,2 active in Rabat |

Load a scenario:

```bash
pnpm demo:seed                                   # write `default` (stop the API first)
pnpm demo:reset                                  # wipe .data and write `default` (stop the API first)
pnpm --filter @naya/demo-api seed first-ride     # any named scenario
curl -X POST http://localhost:4010/dev/reset -H 'Content-Type: application/json' -d '{"scenario":"first-ride"}'
```

In any demo build: Compte → « Lanceur de scénarios » (or tap the « Démo » badge on the welcome screen). It resets
scenarios, lists the accounts, advances the server clock (30 s, 2 min), resolves pending provider jobs and toggles
the simulated driver.

## Oct 6 feedback features

Walkthrough with exact steps: [MOBILE-FEEDBACK-DEMO.md](../MOBILE-FEEDBACK-DEMO.md#walkthrough).

- Naya Famille: Compte → Naya Famille → « Charger l’exemple de démo » creates Lina's child profile, the Essentiel
  plan, Amina as dedicated driver and a weekday trip. Handover codes in the example: Salma `1234`, Youssef `5678`.
  The driver's app never receives these codes; the server checks them, and 5 wrong codes lock the handover (P1).
  A blank or non-4-digit entry is refused without counting. Nothing unlocks a locked trip yet: reset the demo data.
- Passenger wallet: Compte → Portefeuille Naya, then a demo top-up you confirm or refuse yourself (P7).
