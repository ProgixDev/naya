# Passenger app (apps/passenger) — agent notes

Read the root [AGENTS.md](../../AGENTS.md) first. This file adds what is specific to this folder.

Expo SDK 57 app "Naya" (`ma.naya.passagere`, scheme `naya`). Config: `app.config.ts`. Routes: `src/app/` (expo-router, typed routes).
Most screens are thin wrappers over `@naya/ui`; app-only code lives in `src/lib` (session, queries, prefs, route draft),
`src/features` (help, location, ride, schedule, verify) and `src/components`.

## Route guards (src/app/_layout.tsx)
- `(auth)` when signed out; `(verify)` when signed in and identity not approved; `(app)` once approved.
- An opaque cover hides the stack while the account loads, so deep links survive. `dev` is a modal outside the guards.

## Expo rules (replaces the old AGENTS.expo.md)
- Expo changes every SDK. Before touching an Expo or RN API, read https://docs.expo.dev/versions/v57.0.0/
  and https://docs.expo.dev/llms.txt. Never answer from memory.
- Add native modules with `pnpm --filter @naya/passenger exec expo install <pkg>` so versions match SDK 57.
  Never npm, yarn, bun or npx. Check versions with `pnpm --filter @naya/passenger exec expo install --check`.
- Prefer Expo modules over third-party libraries. A new native module affects both apps' builds and TestFlight.
- Config lives in `app.config.ts` (there is no app.json). Native changes go through config plugins in
  `../../plugins/`. `ios/` and `android/` are generated by prebuild and git-ignored: never edit them by hand.
- Native modules (maps, camera, secure store, glass) need a development build, not Expo Go:
  `pnpm --filter @naya/passenger ios` (expo run:ios). Simulator review build: [ios-simulator runbook](../../docs/runbooks/ios-simulator.md).
- TestFlight builds so far are local Xcode archives, not EAS cloud builds: [testflight-eas runbook](../../docs/runbooks/testflight-eas.md).
- Every file in `src/app/` is a route; `_layout.tsx` files are navigators. Keep other code out of `src/app/`.
  Import `Link`, `router`, `useLocalSearchParams` from `expo-router`.
- Before done: `pnpm --filter @naya/passenger typecheck`, `pnpm --filter @naya/passenger lint` (0 errors),
  `CI=1 pnpm --filter @naya/passenger test`. After a dependency change: `pnpm --filter @naya/passenger doctor`.

## Theming
- Styles come from `@naya/tokens` + `useTheme()`. No `className`, no hex or rgba literals in screens.
- Never read `colors.*` at module scope: a module-level `const styles = { … colors.surface … }` keeps the
  light value forever. Use `themedStyles(() => ({ … }))` from `@naya/tokens`, or build styles inside the
  component after `useTheme()`.
- Home (`(app)/(tabs)/index.tsx`) once did this and was unreadable in dark mode (P15, PAX-01); it now uses
  `themedStyles`. The guard in `packages/ui/src/__tests__/theme.test.tsx` (run by this app's jest) fails on colour reads
  at import, components that read colours without `useTheme()`, and colours cached in hooks. Its `KNOWN` list stays
  empty: fix the code, never add an exception.
- Token roles (dark-mode audit, DM rows in the backlog, ADR-0023): control boundaries `outline`, decorative edges
  `hairline`, separators `line`; placeholders `muted`, never `disabledText`. `inverse` is only for text on accent; on
  media (camera) or the fixed plum wallet card use fixed `#FFFFFF`. `shadowColor` is never `colors.ink` (use
  `shadow.*` or fixed `#2E202C`). Spread `frostOutline` and `shadow.*` at render or inside `themedStyles`, never into a
  module-level constant. Check every screen you touch in both schemes.

## State and storage
- Server data through TanStack Query hooks in `src/lib/queries.ts`, keyed with `qk` from `@naya/api`.
- Session: `createSessionStore('passenger')`, key `naya.passenger.session` in SecureStore (sessionStorage on web).
  Device prefs: AsyncStorage `naya.passenger.prefs` (version 2).
- City: the server's `user.cityId` is the truth (ADR-0054, PAX-05). Read it with `useCityId()` (`src/lib/prefs.ts`);
  the prefs only cache it per account (`cityAccountId`). The city picker calls `PATCH /me`.
  Theme: AsyncStorage `naya.theme` (packages/ui).
- Location is foreground only, with a manual pin fallback (`src/features/location`). Do not add background location here.

## Safety and emergency numbers
- The ride screen has no contact sheet while calling and messaging through Naya are not live (R8, 15 Oct 2026): no call
  or message button, no « Bientôt disponible » row. Do not bring them back before a telephony provider (ADR-0031).
- Safety is the pinned « Sécurité » disc (`SafetyDisc` from `@naya/ui`, testID `sos`) on the map's right edge, outside
  the sheet's scroll. Its sheet sends the alert on a 1.5 s hold (`confirm-sos`), then offers « Appeler le 19 »
  (`sos-call-police`) and « Autres numéros d’urgence » (`emergency-numbers`: 15 `call-civil-protection`, 177
  `call-gendarmerie`, 112 as a line). Rules: [docs/specs/safety-sos.md](../../docs/specs/safety-sos.md) R2, R4, R6, R12.
  The ride screen passes the SOS position (car's fresh signal, the phone if location is already allowed, the pickup)
  and its label; keep that order.
- The numbers live in `packages/domain/src/emergency.ts` (`EMERGENCY_NUMBERS`, PAX-11); `src/features/help/emergency.ts`
  re-exports them for the help topic and page. The support form banner in `packages/ui/src/features/support.tsx` still
  repeats them by hand: change both together.
- Status words and glyphs come from `statusPresentation` / `StatusIcon` ([ADR-0059](../../docs/adr/0059-status-is-an-icon-problems-keep-words.md)):
  a glyph alone in rows, the word on heroes and problems, the sentence always in the accessibilityLabel.
